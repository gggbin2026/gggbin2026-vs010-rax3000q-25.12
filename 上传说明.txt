════════════════════════════════════════
★ 根因：Markdown 反引号被 bash 当成命令替换
════════════════════════════════════════
旧写法把整段 Release 说明塞进一个 bash 双引号字符串：
  NOTES="✅ ... 少一项 `gen-config.sh` 直接 `::error::` 阻断 ...
         `bridge-watchdog set-peer <对端新管理IP>` ..."
  gh release create ... --notes "$(printf '%b' "$NOTES")"

双引号里的 Markdown 反引号被 bash 当成【命令替换】执行；
步骤开头是 set -euo pipefail，第一个 command not found 就让整个步骤挂掉，
<对端新管理IP> 里的 < 还触发 syntax error。
这些"命令"全是写给人看的文字，不是真要执行。

前几轮编译都在 make 之前失败（第 52/54/55 次），从没走到 Publish Release；
第 55 次修好后第一次全链跑通，才在最后一步撞上。
