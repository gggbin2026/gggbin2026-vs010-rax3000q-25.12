【根因 1（致命）：内核版本探测让整个步骤 exit 2】
旧 workflow 里：
    KVER=$(make -s kernel_version 2>/dev/null | tr -cd '0-9.' | cut -c1-24)
qosmio 25.12-nss 上这个 make 目标返回非 0；步骤开头是 set -euo pipefail，
命令替换一失败整个 Prepare 就退出码 2；2>/dev/null 又把错误吞了，
所以日志里只看到「[prepare] ✓ 可以开始 make download / make」后直接失败，
make download / make 一行没跑，build.log 自然不存在。

修复：两份 workflow 改成【纯读源码树】，绝不调用 make：
    target/linux/qualcommax/Makefile 的 KERNEL_PATCHVER (=6.12)
  + target/linux/generic/kernel-6.12 的 LINUX_VERSION-6.12 (=.91)
  → KVER=6.12.91，每级都有 || true 兜底，最后回落 baseline.env。
固件名仍带内核版本，但以【源码树实际值】为准，可能与文档里记的
6.12.116 不同，这是正确的，不是写错。git rev-parse 也加了 || echo unknown。

【根因 2：TTYD 和无线固件被自己的脚本删了】
日志 4264/4265 行：
    ::warning::ath11k-firmware-ipq5018-qcn6122 在当前 feeds 中未找到，已从 .config 显式关闭
    ::warning::luci-app-ttyd 在当前 feeds 中未找到，已从 .config 显式关闭
但 feeds install -a 日志里明明有 "Installing package 'luci-app-ttyd' from luci"。
原因：gen-config.sh 旧第 5 段用 `./scripts/feeds list | awk '{print $1}'` 探测，
在 qosmio 树上误判；更讽刺的是 =n 的主题会被 `grep '^...=y$' || continue` 跳过，
它自称的「防主题白屏」一次都没生效，只把必需包删了。日志末尾
"luci-app 数量: 0（只应为 ttyd）" 就是证据。

修复：必需包（dropbear / ttyd / luci-app-ttyd /
ath11k-firmware-ipq5018-qcn6122 / kmod-ath11k-ahb）【永不自动删】，
defconfig 后只核对只警告；只有「主题类且 =y」才做不存在即剔除；
探测改用文件存在性 package/feeds/*/<pkg>/Makefile，不依赖 feeds list 格式。
模拟树实测：4 个必需包全保留，feed 里没有的 argon 主题被正确剔除。

【★ 根因 3：机器狗导致刷机后自动重启 —— 已彻底关闭】
旧默认 WDS：enabled=1 / delay=5 / grace=6，首启脚本还 enable+start。
单机、无对端 WDS、或只当有线网桥时，开机约 6+5≈11 分钟就 reboot -f，
之后每周期反复重启，连 SSH 排障窗口都没有。

现在四层都改了：
  · files/etc/config/wdsdog        → enabled '0' + dryrun '1' 双保险
  · files.ap/etc/config/wdsdog     → enabled '0'（原本就是）
  · WDS 首启 99-bridge-ready 7c 段 → stop + disable，并 uci 强制写 enabled=0
                                     （防 sysupgrade「保留配置」把旧值带回来）
  · /usr/sbin/bridge-watchdog 代码缺省 → enabled 0 / dryrun 1
                                     （配置文件丢失也不再回落成自动重启）
  · banner / 两份 Release NOTES 文案同步
脚本与 init.d【完整保留】，成对 WDS 部署仍可手动：
    bridge-watchdog set-peer 192.168.1.242
    bridge-watchdog set-delay 10
    bridge-watchdog on
    bridge-watchdog dryrun off     # 观察一两天确认不误重启才执行

刷机动作本身仍会【正常重启一次】（原厂 Web API 返回 isreboot=1），
这是刷机流程自带，不是故障；开机之后不会再无故重启。
