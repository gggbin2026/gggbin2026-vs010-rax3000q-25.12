## 二、★ 必须更正：上一轮「UBI CRC 非标准算法」是我算错了

第 42 次决策文档写「209 个 PEB 的 418 个头全部 mismatch（拼写误）、厂商自定义 CRC、不可重打包」
—— **这个结论是错的**。本轮把 CRC 变体枚举全了：

```
EC 头存 0xba1e8d0a   VID 头存 0xb82564a8
zlib.crc32(h[:60],0)               = 0x45e172f5 / 0x47da9b57
~zlib.crc32(h[:60],0)              = 0xba1e8d0a / 0xb82564a8   ★ 完全命中
```

用 `(~zlib.crc32(h[:60],0)) & 0xffffffff` 验证：

| 镜像 | EC/VID 头总数 | 匹配 | 不匹配 |
|---|---|---|---|
| cucc_vs010 好固件 | 418 | **418** | 0 |
| cmcc_rax3000qy 好固件 | 418 | **418** | 0 |

**418/418 全部命中**（两个机型各 418 个 EC/VID 头）。

→ **就是标准 UBI CRC（POSIX/内核 `crc32` 口径），不是厂商自定义。头校验这一层障碍不存在。**

顺带把其它结构也摸清了：

- `PEB=131072`、`LEB=126976`、`min_io=2048`、`data_offset=4096`
- 卷表在 PEB0/PEB1（两份），**172 字节/条**，CRC 在记录内 offset 168：
  `kernel` reserved_pebs=32 / `rootfs`=175 / `rootfs_data`=9
- **`cat /proc/mtd` 实证 `mtd15: 06e00000 = 110MB "rootfs"`**，
  `rootfs_data` 分区 `04e97000 ≈ 82MB`。镜像才 26.1MB → **扩卷绝对放得下**
- U-Boot strings 里有 `ubi.mtd=rootfs root=/dev/ubiblock0_1`、
  `ubi remove rootfs_data && ... && ubi create rootfs_data`

## 三、★ 结果反转：不用源码，产物级融合已经做成并验证通过

第 42 次列的三条障碍，本轮**全部排除**（`oem54/build-fused.py` / `build-fused.sh`）：

| 原障碍 | 怎么解决 |
|---|---|
| 「mksquashfs 重打包 +811008 B，175 LEB 装不下」 | **扩 rootfs 卷 175→183 LEB**，总 PEB 209→217（27.12MB，远小于 `mtd15` 的 110MB）；新增 LEB 用原 VID 头模板改 `lnum` 并重算 `hdr_crc`；卷表 `rootfs.reserved_pebs=183` 并重算记录 CRC |
| 「VID 头 `data_size/used_ebs/data_crc` 全为 0，语义未知」 | **这恰恰是关键便利**：NWRT factory 用「扁平布局」，VID 头不带长度/数据 CRC，所以**替换数据区不触发任何 CRC 变化**。实测 4/4 融合镜像的 217×2 个 EC/VID 头全部校验通过 |
| 「U-Boot 会 `ubi remove rootfs_data`」 | 不预置 `rootfs_data` 卷；定制**直接注入 rootfs squashfs**，首启由 `etc/init.d/oem54-firstboot`（START=99）做 uci 增量配置 |

**已产出 4 个可直接刷的 `fused/` 固件**（`Nwrt-FUSED-5.4.213-<日期>-<机型>-<wds|ap>-squashfs-nand-factory.bin`）：

| 机型 | WDS | AP |
|---|---|---|
| VS010 | ✅ | ✅ |
| RAX3000Q | ✅ | ✅ |

`oem54/verify-fused.py` 对 4 个镜像逐一严格验证，全部 **RESULT: PASS**：

- 217 PEB，rootfs LEB 连续 0..182，kernel 卷 32 LEB

## 四、最终答案：你要的「一个固件刷进去就全都有」已经有了

```
fused/Nwrt-FUSED-5.4.213-<日期>-cucc_vs010-wds-squashfs-nand-factory.bin   VS010 网桥
fused/Nwrt-FUSED-5.4.213-<日期>-cucc_vs010-ap-squashfs-nand-factory.bin    VS010 AP
fused/Nwrt-FUSED-5.4.213-<日期>-cmcc_rax3000qy-wds-squashfs-nand-factory.bin  RAX3000Q 网桥

```

**不需要去别的仓库拉源码**：官方 factory.bin 本身就是「和好固件一样版本」的完整产物，
把它当底座直接注入定制即可。内核 5.4.213、闭源无线、NSS 有线加速、ART、分区
一个字节不动；仓库定制全部编译进 rootfs，首启自动配齐 WDS/AP/防护/页面。

重生成（仓库根目录，需 `unsquashfs`/`mksquashfs`）：

```bash
sh oem54/build-fused.sh --all       # 四个组合全出
python3 oem54/verify-fused.py <新.bin> <原官方.bin> wds VS010
```

GitHub Actions 里 `Build OEM wireless bundle` 也会自动重建 4 个固件并逐个验证。
