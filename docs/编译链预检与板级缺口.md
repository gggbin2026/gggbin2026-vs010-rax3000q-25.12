  所以 `openwrt/build.log` 不存在，artifact 上传也报「No files were found」。

## 二、修完 `.gitignore` 之后会撞上的两关（本次预检新发现）

我把 `qosmio/openwrt-ipq @ 25.12-nss`（HEAD `d6848fa2`）真 clone 下来，
按 `prepare.sh` 的顺序跑了 `board-inject.sh` / `gen-config.sh`，发现两个**必然停编**的问题。

### 关卡 1：DTS 目录布局不匹配（VS010 也会挂）

`board-inject.sh` 旧版只认两种布局：

```
target/linux/qualcommax/dts/       （旧 24.10 风格）
target/linux/ipq50xx/dts/          （QSDK 风格）
```

而 **25.12 / qosmio 实际布局**是：

```
target/linux/qualcommax/files/arch/arm64/boot/dts/qcom/
   ├── ipq5018-pz-l8.dts
   ├── ipq5018-ess.dtsi
   ├── ipq5018-qcn6122.dtsi
   └── ...（17 个 ipq5018 相关 dts/dtsi）
```

`target/linux/qualcommax/dts` 目录**不存在**，第二个分支也不存在 →
旧脚本直接 `::error::不是 ipq50xx 源码树; exit 1`。**两台机型都会挂。**

> 顺带修掉两个小问题：
> - `02_network` 的锚点在 25.12 里是 `cmcc,pz-l8|\`（竖线续行），旧 sed 写死 `cmcc,pz-l8)`
>   匹配不到，注入会静默失败。已改成 `[|)]` 并实测插入行是 `\tunicom,vs010|\`，`sh -n` 通过。
> - `ipq5018.dtsi` 由 Linux 内核源码提供，树内本来就没有；旧脚本每次都刷一条误导性
>   `::warning::树里没有 ipq5018.dtsi`，已改为只检查树内确实存在的两个 dtsi。

### 关卡 2：RAX3000Q 板级在基线 A 里根本不存在

查了 qosmio 25.12-nss 的**整棵树 12317 个路径**：

| 搜索词 | 命中 |
|---|---|
| `rax3000q` | **0** |
| `vs010` | **0** |
| `pz-l8` | 1（`ipq5018-pz-l8.dts`） |

`target/linux/qualcommax/image/ipq50xx.mk` 只有 15 个官方 ipq50xx 设备
（`cmcc_pz-l8` / `elecom_wrc-x3000gs2` / `glinet_gl-b3000` / `linksys_*` / `xiaomi_ax6000` …），
**没有 `cmcc_rax3000q`**。树里那些 `rax3000m` 是 mediatek/MT7981，完全不同的机器。

`baseline.env` 旧注释 `BASE_A_RAX3000Q="native:cmcc_rax3000q"  # 树内原生，实机验证过`

### RAX3000Q 板级的依据与边界

事实来源是用户上传的两个 27 MB 好固件（第 41 次已解包），RAX3000Q 的 FIT 里
`/images/fdt@1` 真实 DTB（43778 B）给出：

```
model      = "CMCC RAX3000QY"
compatible = "cmcc,rax3000qy", "qcom,ipq5018-mp02.1", "qcom,ipq5018"
gpio_keys  = wps(GPIO23, KEY_WPS_BUTTON) + reset(GPIO25, KEY_RESTART)
leds       = sysb(17) / sysg(19) / sysr(25)
wifi       = board_id 0x24(2G) / 0x60(5G), caldb-addr=0
```

DTS 采用**同芯片 PZ-L8 的 6.12 主线骨架**（IPQ5018 + QCN6122 + QCA8337 DSA），改
model / compatible / calibration-variant，并把 `&q6v5_wcss`、`&wifi`、`&wifi1`
从上游的 `disabled` 改成 `okay`（上游 PZ-L8 默认关 WiFi，注释说是怕 256M 内存 OOM）。

⚠ **如实说明三件事**：

1. **未在 6.12 主线实机验证**。5.4 闭源 `ipq_cnss2` 的 GPIO/LED 到主线 ath11k/DSA 的映射
   不一定等价。为避免「悬空 GPIO 被配成按键 → 开机误进 failsafe」（VS010 踩过的坑），
   新 DTS **故意不定义 keys / leds**。按键和指示灯不是 AP/网桥的必要功能。
2. **ART 头是全 FF**，所以 DTS **不引用 nvmem macaddr**；MAC 请按机身标签用 `uci` 固化，
   `art-check` 会提示。端口 label 沿用 PZ-L8 的 DSA 映射，可能与丝印不一致，
   但 WAN+LAN 都在 `br-lan`，不影响哑 AP 功能。
3. **首次刷务必接 3.3V USB-TTL**。若双频/网口异常，先用 `device=vs010` 单编验证编译链，
   再决定要不要继续调 RAX3000Q 板级。

`board-inject.sh` 在编译时会打印对应的 `::warning::`，Release notes 也会带这条提示。

```
[gen-config] 设备符号 = CONFIG_TARGET_qualcommax_ipq50xx_DEVICE_cmcc_rax3000q
02_network 注入后 sh -n 语法 OK
```

**没验证到的**：`make defconfig` 的完整结果。本机沙盒的 `awk` 是 `mawk`，
`include/scan.awk` 用到 GNU awk 的 `asort` → `tmp/.targetinfo` 变成 0 字节 →
`defconfig` 会把所有设备符号丢掉，这是**沙盒假阳性**。
GitHub Actions 的 apt 步日志明确显示 `gawk is already the newest version (1:5.1.0-...)`，
且装了 `libncurses-dev`，所以 CI 里不会出现这个症状。
`gen-config.sh` 已加 gawk 检测与三条排错提示，真出问题会在日志里说清楚。

另外 `./scripts/feeds update -a && install -a` 后 `gen-config.sh` 的「feed 里不存在的包
显式关闭」才会正常工作；沙盒没跑 feeds，`ttyd` / `ath11k-firmware-ipq5018-qcn6122`
被判为不存在只是假阳性（后者在主树 `package/firmware/ath11k-firmware/Makefile`
里确实有 `define Package/ath11k-firmware-ipq5018-qcn6122`）。

   是否注入 `TARGET_DEVICES`、`awk` 是否 gawk、feeds 是否 update/install。
