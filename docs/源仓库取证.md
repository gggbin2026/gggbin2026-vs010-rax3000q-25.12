# xiangye277/vs010-openwrt 取证（2026-11-28 实克隆）

`reference/xiangye277/` 是克隆下来的**编译相关文本文件**（不含 85MB 的
`firmware/*.zip`、`oem_extract/rootfs.ubi` 等二进制）。

## 实测事实

`.github/workflows/build.yml`：

- `git clone --depth=1 --single-branch https://github.com/openwrt/openwrt.git`
  —— **没有 `-b`，没有 tag，没有 commit**。所谓「这个内核和版本」实际上不存在锁定值，
  每次编译拉的是官方主线当时的最新快照，内核版本随上游滚动。
- `./scripts/feeds update packages luci routing` + `install -a -p ...`
- `cp ipq5018-vs010.dts openwrt/target/linux/qualcommax/dts/`
  —— 旧布局；25.12 的 DTS 在
  `target/linux/qualcommax/files/arch/arm64/boot/dts/qcom/`（第 43 次实证），
  直接拷会落错目录、设备定义找不到 DTS。
- 往 `target/linux/qualcommax/image/ipq50xx.mk` 追加 `Device/unicom_vs010`，
  `DEVICE_DTS_CONFIG := config@mp02.1`，`IMAGES += factory.img`，
  `IMAGE/factory.img := append-ubi | qsdk-ipq-factory-nand`。
- `DEVICE_PACKAGES` 25 个包：luci + 中文 + smartdns / https-dns-proxy / adblock /
  sqm / wireguard / curl / wget-ssl / iperf3 / htop / nano …
- `sed -i` 往 `02_network` 插 `unicom,vs010|`。
- `.config` 只有 4 行：`TARGET_qualcommax` / `ipq50xx` / `DEVICE_unicom_vs010` /
  `ROOTFS_SQUASHFS` / `ATH11K_MEM_PROFILE_256M`，然后 `make defconfig` + `make -j$(nproc)`。

README 自己写着：

> 此固件基于 CMCC PZ-L8 设备树改编，GPIO 配置可能与实际 VS010 有差异。
> 首次刷入有砖风险，建议准备好 TTL 串口线用于救砖。

25.12 仓库历史结论（第 44 次）进一步注明：该 fork 来源的 DTS **已被作者本人否定**
（GPIO 与 switch port 配置有误）。

## 结论：能迁移什么，不能迁移什么

**能迁移（本仓已落地）**

- 官方 `openwrt/openwrt` 源码树这个**本质**；
- `ATH11K_MEM_PROFILE_256M`（256MB 机器跑 ath11k 必须）；
- `Device/unicom_vs010` 的设备名 / vendor / model / `config@mp02.1` / NAND 几何；
- Web API 刷机路径（`FLASHING.md` 已归档）。

**不能迁移**

- 「版本」——原仓没有锁，本仓改锁 `v25.12.6`，并留 `source_ref` 覆盖；
- 那份 PZ-L8 改编 DTS（作者否定 + 实机 GPIO/switch 不对）；
- `qualcommax/dts/` 的旧注入路径；
- 25 个科学/下载/统计插件（与「稳定、占用低、无线开启快」直接冲突）；
- `02_network` 的 sed 粘连式注入（本仓用 python 精确锚点 + 续行兼容）。

## 一句话

**能提取文件，不能照抄编译链。** 原仓给的是「用官方树编 VS010」的思路，
本仓把它升级成「锁版本 + 双机型 + 双模式 + 可注入板级 + 精简 + UBNT 界面」。
