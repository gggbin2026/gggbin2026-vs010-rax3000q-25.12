## 四、坚决不改的 5 项（比改了更重要）

1. **RAX3000Q 的 keys / leds 一律不定义。**
   核查报告与恩山 2026-04-25 变砖实录给出完整因果：VS010 刷入 RAX3000Q 的
   U-Boot + 大分区后，因**复位键 GPIO 不一致**被开机持续采样为「按下」，
   循环重启、TTL 无法中断、最终需编程器。官方 3000Q 是 reset=GPIO23 / mesh=GPIO38，
   而好固件 FDT 给出的是 wps(GPIO23) / reset(GPIO25)——**两套来源本身就冲突**。
   按键/LED 不是哑 AP 的必要功能，猜错就是硬砖 → 宁可不定义。
2. **VS010 的 QCA8337 端口排序不改。**
   报告说 PZ-L8 改编版「按公版排序，错」，正确基线是 maxdarksol 版（LAN3 直连
   CPU 作 WAN），但**该版全文没取到**，只有文字描述。改错会网口全灭。
   由于 WAN+LAN+2.4G+5G 全在 `br-lan`，label 错位不影响桥接功能 →
   保留可编译的 PZ-L8 映射，刷后逐个试口。
3. **5G `bdf-addr` 不改。** 原厂 FDT `0x4d300000` 是 5.4 闭源 cnss2 的预留内存，
   主线 ath11k/PZ-L8 骨架是 `0x4d100000`，两套内存布局不同，照抄会让射频读错 BDF。
4. **不抄 `boot-args`。** 官方 main 的 `<0x2 4 2 27 0 0>` 用于让 QCN6102 落 UPD ID 2；
   qosmio 25.12-nss 整树没有任何 `boot-args` 用法，绑定不同。若实机 5G 报
   `expect it to be on UPD ID 3`，再按本树绑定另找方案，不在编译前硬塞。
5. **不整份替换成官方/还原稿 DTS。** 官方 main 用 `&gmac1` / `&uniphy0` /
   `ethernet-ports` / `qcom,calibration-variant`；qosmio 25.12-nss 用 `&dp1/&dp2` /
   `&switch` / `ports` / `qcom,ath11k-calibration-variant`。整份替换会编译失败。
   本仓做法是**只提取硬件真值，按目标树绑定融合**。

## 五、刷机前 / 刷机后必看

### 刷前备份（核查报告「Step 0」）

TTL 或 SSH 进原厂/Nwrt，至少落盘并各算一次 md5：
`0:MIBIB`(mtd1)、`0:APPSBLENV`(mtd10)、`0:APPSBL` / `0:APPSBL_1`(mtd11/12)、
**`0:ART`(mtd13，1 MiB，无线校准 + MAC，不可再生)**、**`0:TRAINING`(mtd14)**、
BOOTCONFIG / DEVCFG / CDT 三对。有条件整片 `nanddump` 一份。
**VS010 绝不刷 CMCC 机型的 U-Boot / MIBIB / 大分区包。**

### 刷后排查

| 现象 | 先查 |
|---|---|
| 某个网口不通 | 上级线逐个换口（VS010 端口 label 待实证，见第四节第 2 条） |
| WAN/LAN 没进 `br-lan` | `board_name` 是否命中 `cmcc,rax3000q` / `cmcc,rax3000qy` / `unicom,vs010`；`02_network` 是否已注入 |
| 5G 不 probe | `dmesg | grep -i ath11k`；若报 UPD ID 3，看第四节第 4 条；确认 `q6v5_wcss` 与 `&wifi1` 都是 `okay` |
| LuCI 操作 OOM | 官方因 256 MiB 关 WiFi；本仓已配 256M 低内存 profile，仍 OOM 则社区做法是 `ath11k-smallbuffers` + zram（**报告建议，未在两台实机验证**） |
| `unknown flash` / `-74 EUCLEAN` | 闪存批次差异：VS010 是 4bit/512、RAX3000Q 是 8bit/512（GD5F1GQ5REYIG）；东芯变体不支持 8bit，删掉 DTS 里两行 `nand-ecc-*` 重编让驱动协商。`nand_patch` 仍默认关 |
| 开机误进 failsafe | 确认 DTS 里**没有** `KEY_RESTART` / `label="reset"`；`verify.sh` 已硬校验 |

### 编译

`nand_patch` / `ART_CALIBRATION` / `ssh` 保持关；**`device` 先选 `vs010` 单跑一次**，
成功再 `both`（RAX3000Q 板级仍是实验性注入，未在 6.12 主线实机验证）。

## 六、证据边界（不夸大）

- `vs010.dtb` 是**原厂 5.4 闭源栈**的运行态 FDT，与第 41 次从 factory.bin FIT 抽的
  `vs010.real.dtb` **MD5 不同**（`5f849ed9…` vs `4e6b279b…`），可能是不同固件版本；
  但按键 / LED / ECC / 分区这些硬件字段一致，可交叉印证。

  已用 main 分支官方原文校验，差异处已标注。
