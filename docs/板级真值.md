# 板级逐项真值（第 43 / 44 次结论）

## 为什么要注入

- RAX3000Q/QY 2026-09-27 才合入 OpenWrt **main**；
- `v25.12.6` 稳定 tag 与 `qosmio 25.12-nss` 树里 **整树 0 命中 rax3000q**；
- VS010 从来不在官方树里。
→ 四条基线都需要 `scripts/board-inject.sh` 注入两台板级。

## VS010（`board/ipq5018-vs010.6.12.dts`）

基底：OpenWrt main 的 `ipq5018-pz-l8.dts` 还原版（见 `reference/old54/`）。

| 项 | 值 | 来源 |
|---|---|---|
| model / compatible | `CUCC VS010` / `cucc,vs010`, `qcom,ipq5018` | 实机 DTB |
| LED | mesh = GPIO33、pwr = GPIO31（原 PZ-L8 是 GPIO35/30，已改） | 第 44 次实机校正 |
| 按键 | **不定义** | 恩山变砖实录：复位键 GPIO 冲突 → 循环重启 / TTL 失联 / 编程器 |
| NAND ECC | 4bit / 512 | 第 44 次补 |
| switch 端口排序 | **不改** | 正确基线未取到，改错网口全灭；WAN+LAN 全在 br-lan，label 错位不影响桥接 |
| `qcom,bdf-addr` / boot-args | **不改** | 真实 DTB 里那是 cnss2 的，禁止抄进 ath11k DTS |
| wifi 节点 | `status = "okay"`（官方 DTS 是 disabled） | 本仓要无线；配 256M LOW |

## RAX3000Q（`board/ipq5018-rax3000q.6.12.dts`）

基底：OpenWrt main 的 `ipq5018-rax3000q.dts` 还原版。

| 项 | 值 |
|---|---|
| compatible | 双写 `cmcc,rax3000q` + `cmcc,rax3000qy` |
| QCA8337 | PHY0=WAN、PHY1/3/4=LAN1/2/3，port@0 单条 SGMII CPU 链路（官方映射整段保留） |
| NAND ECC | 8bit / 512（GD5F1GQ5REYIG，原文件已带） |
| 按键 | **不定义** |
| wifi 节点 | `status = "okay"` |

## 坚决不做

1. 不定义 keys（两台）；
2. 不整份替换 DTS、不改 5G `bdf-addr`、不改 `boot-args-append`；
3. 不把 ART 切片编进固件（`ART_CALIBRATION=0`）；
4. 不按 phy 编号标射频温度（一次 wifi reload 就能让 2.4G 从 phy0 变 phy1）；
5. 不猜默认路由判端口归属（读 sysfs 桥成员 + `eth*` + 无线口动态补齐）。

⚠ **未在 6.12 主线实机验证**：按同芯片 PZ-L8 骨架 + 好固件 FIT 真实 DTB 融合。
首次刷必接 TTL，建议 `device=vs010` 单跑成功后再 `both`。
