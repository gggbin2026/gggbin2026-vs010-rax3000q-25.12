# 单包双模式 + 轻量巡检（本次两项合并）

## 一、单包：一个机型 1 个固件，AP ⇄ WDS 不重刷

| | 上一版 | 本版 |
|---|---|---|
| 入口 | `build-wds.yml` / `build-ap.yml` 两个 | **一个 `build.yml`** |
| 产物 | 一机型 2 套固件 | **一机型 1 个固件**（`device=both` 一次出 2 个：VS010 + RAX3000Q） |
| 换模式 | 重刷另一套 | 界面里切，**不重刷** |
| 文件名 | `Nwrt-WDS-<内核>-...` / `Nwrt-AP-<内核>-...` | `Nwrt-WDS-AP-UBNT-<内核>-<日期>-<机型>-dual-<原名>` |
| Release tag | `...-wds` / `...-ap` | `fw-<内核>-<run_id>-<机型>-dual` |

`default_mode`（默认 `wds`）只写进 squashfs 的 `/etc/nwrt/mode` 与
`/etc/nwrt/default_mode`；切换写 overlay，刷机不勾「保留配置」就回默认。

> **管理 IP 与 mode 完全解耦**：WDS ⇄ AP 切换、开机重放 `user.cfg` 都**不会改 IP**。
> `/etc/nwrt/ipaddr` / `netmask` 覆盖文件与面板 ⑤ 的 ip/mask 只由用户主动改，
> 两个脚本只读不删不写；`role=client` 也不再自动写死 `.242`。详见 `FIRMWARE.md`。

### 三条切换路径（效果完全一致）

1. **LuCI（推荐）**：`/cgi-bin/luci/admin/nwrt` →「WDS / AP 模式」页，两个按钮。
   端点在 `admin` 树下继承 `root.sysauth`，未登录 302 到登录页；
   `mode` 白名单只有 `wds|ap`，零 eval、零参数注入面。
2. **TTYD / SSH / 串口**：`nwrt-apply-mode wds` 或 `nwrt-apply-mode ap`。
   状态页「服务与防护」里有「复制命令」按钮 + TTYD :7681 直达。
3. **兜底说明**：某些基线（官方 25.12 的 LuCI 若已 ucode 化）可能没编
   `luci-compat`，Lua controller 不会被 dispatch、页面 404。**不假装能点**：
   用第 2 条即可，效果一致。这是如实说明，不是缺陷包装。

### 切换动作（沿用 5.4 老仓 STANDARDS 红线）

写 `/etc/nwrt/mode`(600) → 清 applied stamp → `nwrt-apply-mode` 只改**既有**
`wifi-device` / `wifi-iface` 的 option 与 `disabled` → **一次** `wifi reload` →
清 `/tmp/luci-*` 缓存 + `uhttpd reload`。

- 不重建 radio、不 `wifi down`、不重启机器、不新增常驻进程；
- WDS 只用 5G 4addr（`NWRT-WDS` / `WDS123456`），2.4G `disabled=1`；
- AP 双频（`NWRT-AP-2G` / `NWRT-AP-5G` / `AP123456`），清 `wds`；
- 根路径 `/` 按当前 mode 跳 `/bridge/` 或 `/ap/`；三页仍全互访，
  打开非当前模式的页只显示一条**非强制提示条**，不 2 秒踢走。

## 二、轻量巡检：单个 `nwrt-tick`

| 项 | 值 |
|---|---|
| 常驻数 | **1 个**（procd `respawn 3600 5 0`，挂了自动拉起） |
| 周期 | 60 秒一轮，分频：NTP 每 5 轮（300s）、WDS 关联每 2 轮（120s） |
| 出厂动作 | `DRYRUN=1` —— **只记日志与 `/tmp/nwrt-tick.status`，不自动动作** |
| 允许自愈 | 改 `DRYRUN=0` 后，仅在「无关联 + 距上次 ≥30 轮」时做**一次** `wifi reload` |
| 红线 | 不 `wifi down`、不重启、不循环 reload、不新增第二个常驻 |
| 无工具时 | `iw` 不在 / 无无线口 → 状态如实写「跳过」，绝不伪造关联数 |

配置在 `/etc/nwrt/tick.conf`（只取数字，非法值回落默认）：

```
ENABLED=1  TICK_SEC=60  NTP_EVERY=5  WDS_EVERY=2
DRYRUN=1   RELOAD_COOLDOWN=30  NTP_SERVER=172.10.10.254
```

NTP 用 busybox `ntpd -n -q -p`，服务器是纯 IP，不依赖本机 DNS；
不可达只记日志，不报错、不阻断。

对比 5.4 老仓：那边是 `vs010-tick` 单常驻 + `bridge-watchdog`（出厂停用）。
本版只保留一个 `nwrt-tick`，把 NTP / 关联巡检 / 状态快照合进去，
默认 dryrun 相当于「机器狗装了但出厂不咬人」，需要时改一个数字就开。

### 开机顺序

```
18 luci-fix → 21 bridge-netfix → 22 l2-guard → 23 no-firewall
→ 24 nwrt-mode（重放模式） → 25 nwrt-tick（唯一常驻）
```

## 三、边界

- ⚠ **NSS 卸载后部分报文不过 host bridge hook**：`l2-guard` 与 WDS 关联巡检
  都属尽力防护，不是硬保证。
- 切换模式**不会**改 IP（仍 `172.10.10.241/22`）、不会动防火墙/IPv6 关闭态、
  不会重启 `nwrt-tick`（它每轮重读 `/etc/nwrt/mode` 自动跟随）。
- 本版是静态重建 + 本地自检，没在 Actions 真跑过 `make`；LuCI controller 是否
  被 dispatch 取决于所选基线的 `luci-compat`，故留了命令兜底。
