### 根因：Markdown 反引号被 bash 当成命令替换

旧写法把整段 Release 说明塞进一个 bash 双引号字符串：

```bash
NOTES="✅ ... 少一项 `gen-config.sh` 直接 `::error::` 阻断 ... `bridge-watchdog set-peer <对端IP>` ..."
gh release create ... --notes "$(printf '%b' "$NOTES")"
```

双引号里的 **Markdown 反引号**被 bash 当作**命令替换**执行；`set -euo pipefail` 下
第一个 `gen-config.sh: command not found` 就足以让整个步骤挂掉，`<对端新管理IP>`
里的 `<` 还触发了 `syntax error`。这些"命令"其实全是我们写给**人看**的文字。

之前几轮编译都在 `make` 之前就失败，从没走到 Publish Release，所以这个隐患
一直没暴露；第 55 次修好后第一次全链跑通，才在最后一步撞上。

### 修法：说明文本彻底脱离 shell 字符串

| 改动 | 说明 |
|---|---|
| 🔴 新增 `release/RELEASE-NOTES-WDS.md` / `-AP.md` | 纯 Markdown 文件，反引号、`$`、反斜杠全部按字面保存；**不经过 shell 解释** |
| 🔴 两份 workflow 改用 `gh release create --notes-file "$NOTES_FILE"` | 不再有 `NOTES="..."` 双引号赋值，不再有 `printf '%b' "$NOTES"` |
| 元信息（基线 / 内核 / 源码 HEAD / NAND 开关 / 生成时间） | 用几行**不含反引号**的 `echo` 追加到临时文件，变量正常展开 |
| `mktemp` 临时文件 + `rm -f` | 不污染 `firmware_out/*`，不会把说明文件当固件传进 Release |
| `verify.sh` 第 56 次判据 | 两份 workflow 的 Publish 代码行**不允许出现反引号 / 旧 NOTES 赋值**，必须 `--notes-file` + 引用 `release/*.md` |
